# **1. SQL** (_Structured Query Language_)

## **1.1 SUBLINGUAGENS SQL**

### **1.1.1 [[DDL]] (_Data Definition Language_)**
Define a ESTRUTURA (Esqueleto).
- `CREATE`: Cria tabelas/views.
- `ALTER`: Modifica colunas.
- `DROP`: Apaga a estrutura.
- `TRUNCATE`: Apaga os dados, mas mantém a estrutura (esqueleto fica limpo).

### **1.1.2 [[DML]] (_Data Manipulation Language_)**
Manipula os DADOS (Carne).
- `INSERT`: Insere linhas.
- `UPDATE`: Atualiza linhas.
- `DELETE`: Apaga linhas.

### **1.1.5 [[DQL]] (Data Query Language)**
- `SELECT`: Consulta dados.

## **4. Diferentes tipos de JOINs (SQL)**

![[sql joins.png]]

#### **4.1 INNER JOIN**
Retorna a **INTERSEÇÃO**. Só o que tem correspondência em AMBAS.
> *Ex: Clientes que compraram (Lista Clientes que têm pedido).*

#### **4.2 LEFT JOIN**
Retorna **TUDO da Esquerda** + Correspondência da Direita. Se não tiver na direita, vem NULL.
> *Ex: Todos os Clientes, mesmo os que nunca compraram (Pedidos virão NULL).*

#### **4.3 FULL OUTER JOIN**
Retorna **TUDO de Ambas**. Onde não casar, preenche com NULL.

### 🧠 Adendos do Gemini

- **TRUNCATE vs DELETE:**
    - `DELETE` é DML. Pode usar `WHERE`. Gera log (pode fazer rollback se tiver transação). É mais lento.
    - `TRUNCATE` é DDL. Apaga TUDO de uma vez. Não usa `WHERE`. É muito mais rápido (reseta a tabela).
- **Ordem de Execução do SELECT:** A banca vai te pedir a ordem lógica. Decore:
    1.  `FROM` (Pega a tabela)
    2.  `WHERE` (Filtra linhas)
    3.  `GROUP BY` (Agrupa)
    4.  `HAVING` (Filtra grupos)
    5.  `SELECT` (Escolhe colunas)
    6.  `ORDER BY` (Ordena)
