# **1.SQL** (_Structured Query Language_ - Linguagem de Consulta Estruturada)

- É a linguagem padrão para acesso e manipulação de banco de dados.

# **2. SUBLINGUAGENS SQL**

![[Sublinguagens SQL 1.png]]

## **DDL (_Data Definition Language_) –**  **Linguagem de Definição de Dados** 

São os comandos que interagem com os objetos do banco:

| Instrução | Finalidade                                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| CREATE    | Criar uma tabela em um banco de dados                                                                                               |
| ALTER     | Promove uma alteração na tabela: alterando, adicionando ou descartando colunas e restrições                                         |
| TRUNCATE  | Remove todas as linhas de uma tabela ou partições especificadas de uma tabela, sem registrar as exclusões de linhas indivduais      |
| DROP      | Remove uma ou mais definioes de tabela e todos os dados, índices, gatilhos, restrições e especificações de permissão dessas tabelas |
| RENAME    | Renomeia uma tabela criada no banco de dados                                                                                        |

## **DML (_Data Manipulation Language_) – Linguagem de MANIPULAÇÃO de Dados**

São os comandos que interagem com os dados dentro das tabelas:

| Instrução | Finalidade                         |
| --------- | ---------------------------------- |
| INSERT    | Uma nova linha na tabela           |
| UPDATE    | Atualiza uma linha existente       |
| DELETE    | Deletar uma linha                  |
| MERGE     | Mescla duas linhas ou duas tabelas |

## **DCL (_Data_** _Control Language_**) Linguagem de Controle de Dados**

São os comandos para controlar a parte de segurança do banco de dados:

| Instrução | Finalidade                                                          |
| --------- | ------------------------------------------------------------------- |
| GRANT     | Concede explicitamente uma ou mais permissões                       |
| DENY      | nega explicitamente uma ou mais permissões à entidadde de segurança |
| REVOKE    | Remove as permissões **GRANT** ou **DENY** existentes               |

## **DTL _(Data Transaction Language)_ - Linguagem de Transação de Dados.**

São os comandos para controle de transação..

| Instrução | Finalidade                         |
| --------- | ---------------------------------- |
| COMMIT    | Salvar permanentemente a transação |
| ROLLBACK  | Desfazer a transação               |
| SAVEPOINT | Salvar temporariamente a transação |

## **DQL (Data Query Language)** **- Linguagem de Consulta de dados.**

São os comandos de consulta.

| Instrução | Finalidade              |
| --------- | ----------------------- |
| SELECT    | É o comando de consulta |

**<span style="color:#fb4934">Observação</span>:** <span style="color:#fb4934">Em alguns livros o SELECT fica na DML em outros tem esse grupo próprio.</span>

O <span style="color:#fb4934">CREATE TABLE</span> comando cria uma nova tabela no banco de dados.

**Exemplo:**

**<span style="color:#83a598">CREATE TABLE</span>** Gurujas(  
  
   CPF int,  
  
   UltimoNome varchar(<span style="color:#fb4934">255</span>),  
  
   PrimeiroNome varchar(<span style="color:#fb4934">255</span>),  
  
   Endereco varchar(<span style="color:#fb4934">255</span>),  
  
   Cidade varchar(<span style="color:#fb4934">255</span>)  
  
);

# **3. DROP**: exclui uma tabela do banco de dados

**<span style="color:#83a598">DROP TABLE</span>** Gurujas

# **4. TRUNCATE TABLE**

O <span style="color:#fb4934">TRUNCATE TABLE</span> **==comando exclui os dados dentro de uma tabela, mas não a tabela em si.==**

O seguinte SQL exclui os dados da tabela "Gurujas": 

<span style="color:#83a598">TRUNCATE TABLE</span> Gurujas;

# **5. ALTER TABLE**

A instrução <span style="color:#fb4934">ALTER TABLE</span> é usada para adicionar, excluir ou modificar colunas em uma tabela existente.

O SQL a seguir adiciona uma coluna "Aprovacoes" à tabela "Gurujas":

<span style="color:#83a598">ALTER TABLE</span> Gurujas  
<span style="color:#83a598">ADD</span> Aprovacoes varchar(<span style="color:#fb4934">255</span>);

A instrução ==ALTER TABLE== também é usada para adicionar e remover várias restrições em uma tabela existente.

# **6. Restrições SQL**

- **São usadas para especificar regras para os dados em uma tabela:**
- Por exemplo: podem delimitar quais tipo de dados que podem entrar em uma tabela. 

As seguintes restrições são comumente usadas em SQL:

- `**NOT NULL**`- Garante que uma coluna não pode ter um valor NULL
- `**UNIQUE**`- Garante que todos os valores em uma coluna sejam diferentes
- `**PRIMARY KEY**`- Uma combinação de a `NOT NULL`e `UNIQUE`. Identifica exclusivamente cada linha em uma tabela
- `**FOREIGN KEY**` - Impede ações que destruiriam links entre tabelas
- `**CHECK**`- Garante que os valores em uma coluna satisfaçam uma condição específica
- `**DEFAULT**`- Define um valor padrão para uma coluna se nenhum valor for especificado
- `**CREATE INDEX**`- Usado para criar e recuperar dados do banco de dados muito rapidamente

# **7. Comandos Importantes:**

- **DML = "Dados em Movimento":** Pense que a DML é sobre mexer (mover, adicionar, mudar, tirar) nos _dados_ que já estão na tabela.
- **CRUD da DML:** A DML abrange as operações básicas de **C**riar (INSERT), **R**ecuperar (SELECT), **U**pdate (UPDATE) e **D**eletar (DELETE) dados.
- **"SELECT" é o OLHO:** Use SELECT para "olhar" os dados.
- **"INSERT" é a ENTRADA:** Use INSERT para "colocar" dados novos.
- **"UPDATE" é a MUDANÇA:** Use UPDATE para "trocar" dados existentes.
- **"DELETE" é a SAÍDA:** Use DELETE para "remover" dados.
- **UPDATE = Atualizar/Mudar:** Pense em "Update" como a ação de "trocar" ou "modificar" algo que já existe.
- **SET = O QUE MUDAR:** O `SET` é como "definir" os novos valores para as colunas.
- **WHERE = QUEM MUDAR:** O `WHERE` é o "filtro" que garante que você só mude os registros certos, evitando desastres! **Sempre use WHERE para evitar atualizar TUDO!**
- **Pensamento: "Atualizo na Tabela X, Defino esses valores, Onde a condição for Y."**
- **`FROM` é essencial:** Sempre `DELETE FROM` a tabela. O `FROM` indica de qual tabela você está removendo os registros.
- **`WHERE` é a MURALHA:** O `WHERE` é _ainda mais crítico_ aqui do que no `UPDATE`! Ele é a sua "muralha de segurança". **SEMPRE, SEMPRE, SEMPRE USE `WHERE` com `DELETE` (a menos que você queira apagar TUDO).**
- **`DELETE` vs. `TRUNCATE`:** Lembre-se: `DELETE` apaga registros (linhas) e mantém a estrutura. Se você esquecer o `WHERE`, `DELETE` apaga _todos_ os registros, mas ainda é diferente de `TRUNCATE` (que é DDL e reseta a tabela, removendo todos os dados e, em muitos casos, resetando a contagem de IDs).

# **8 - JOIN:**

- **JOIN = Conectar Tabelas:** Pense em `JOIN` como um "conector" ou "ponte" entre duas (ou mais) tabelas, usando uma coluna em comum.
    
- **Tipos de JOIN e Círculos de Venn (Visualize!):** A melhor forma de memorizar os JOINs é visualizando os diagramas de Venn que o próprio material apresenta.
    
    - **INNER JOIN = Onde SE ENCONTRAM:** É a interseção! Pense no "miolo" dos círculos de Venn. Só traz o que existe IGUAL em _ambas_ as tabelas. **É o mais comum!**
        
        - _Bizus Mão:_ Junte as duas mãos, apenas os dedos que se tocam são o `INNER JOIN`.
    - **LEFT JOIN = Tudo da ESQUERDA + O Que Conecta:** Pega _tudo_ do lado esquerdo (a primeira tabela que você menciona após `FROM`) e só o que combina do lado direito. Se não tem correspondência na direita, os campos da direita vêm como `NULL`.
        
        - _Bizus Mão:_ Com a mão esquerda aberta e a direita tocando alguns dedos, o `LEFT JOIN` é tudo da mão esquerda (aberta) e o que toca da direita.
    - **RIGHT JOIN = Tudo da DIREITA + O Que Conecta:** O oposto do `LEFT JOIN`. Pega _tudo_ do lado direito (a tabela após `RIGHT JOIN`) e só o que combina do lado esquerdo. Se não tem correspondência na esquerda, os campos da esquerda vêm como `NULL`.
        
        - _Bizus Mão:_ Com a mão direita aberta e a esquerda tocando alguns dedos, o `RIGHT JOIN` é tudo da mão direita (aberta) e o que toca da esquerda.
    - **FULL OUTER JOIN = TUDO + NULOS (se não tiver):** Pega _tudo_ de _ambas_ as tabelas. Se um registro existe em uma tabela, mas não na outra, os campos da tabela sem correspondência virão como `NULL`. É a união de tudo.
        
        - _Bizus Mão:_ Junte as duas mãos e imagine que você quer todos os dedos de ambas as mãos, mesmo os que não se tocam.
    - **SELF JOIN = Tabela Fala Consigo Mesma:** É um `JOIN` de uma tabela _com ela mesma_. Pense em hierarquias (gerente e empregado na mesma tabela) ou comparações dentro da mesma lista.
        
        - _Bizus Mão:_ Pegue uma mão e faça ela "dar as mãos" para si mesma de alguma forma.
- **`ON` = A Condição do Encontro:** O `ON` é onde você especifica _qual coluna em comum_ as tabelas devem usar para se conectar. É a "chave" do encontro. (`JOIN ... ON coluna1 = coluna2`)

# **9 - FROM**

- **`FROM` = ONDE ESTÃO OS DADOS?:** Pense no `FROM` como o "endereço" ou a "origem" das suas informações. Ele diz ao SQL _de qual tabela(s)_ você quer buscar.
- **`FROM TABELA1, TABELA2` = PERIGO! PRODUTO CARTESIANO!** **Cuidado redobrado aqui!** Listar tabelas com vírgula no `FROM` **sem uma condição de `JOIN` explícita** gera um "tudo com tudo".
- **PRODUTO CARTESIANO = MULTIPLICAÇÃO DE LINHAS:** Se a Tabela A tem X linhas e a Tabela B tem Y linhas, o resultado do Produto Cartesiano terá X×Y linhas. Cada linha da primeira se combina com CADA linha da segunda.
- **"TUDO COM TUDO":** Visualize: se tem 3 professores e 2 disciplinas, o produto cartesiano vai mostrar 3x2=6 combinações: Professor1 com Disciplina1, Professor1 com Disciplina2, Professor2 com Disciplina1, etc.
- **Evite o Produto Cartesiano (a menos que saiba o que está fazendo!):** Na maioria dos casos, quando você quer combinar tabelas, você precisa de um `JOIN` (INNER, LEFT, etc.) com uma cláusula `ON` para definir _como_ elas se relacionam, e não simplesmente juntar todas as combinações possíveis.
