# **1.CONCEITO GENÉRICO DE BANCO DE DADOS**

- Um banco de dados (BD) (ou repositório de dados ou depósito de dados) é uma **<span style="color: #d79921">coleção de dados relacionados</span>** entre si com uma finalidade específica.

# **2. CONCEITO ESPECÍFICO DE BANCO DE DADOS**

Um banco de dados deverá possuir as seguintes características:

- Um banco de dados deve ser projetado, construído e populado com **dados logicamente coerente e com um determinado significado inerente**;
- Deve possuir um **conjunto predefinido de usuários e aplicações**;
- **Representar algum aspecto do mundo real**, o qual é chamado de “mini-mundo”. Qualquer alteração efetuada no mini-mundo é automaticamente refletida no banco de dados.

**Definição simplificada de Banco de Dados:**

_“<span style="color: #d79921">Conjunto de dados integrados (logicamente relacionados) que tem por objetivo atender a uma comunidade de usuários (finalidade específica)</span>”_

# **3. CONCEITO DE SISTEMA GERENCIADOR DE BANCO DE DADOS (SGBD)**

_“<span style="color: #d79921">Software que incorpora as funções de definição, recuperação e alteração de dados em um banco de dados.</span>”_

# **4. CONCEITO DE SISTEMA DE BANCO DE DADOS**

Um sistema de Banco de Dados é formado por:

1. Dados (banco de dados)
2. Hardware
3. Software (SGBD)
4. Pessoas (usuários e técnicos)

De maneira simplificada, podemos dizer que:

**<span style="color: #d79921">Sistema de Banco de dados = Banco de dados + SGBD</span>**

# **5. PRINCIPAIS CARACTERÍSTICAS DE UM BANCO DE DADOS**

Segundo Elmasri, 2011, as características abaixo podem distinguir a abordagem de banco de dados:

- Natureza de **autodescrição** de um sistema de banco de dados;
	- O banco de dados possui em seu sistema não só o conjunto de dados, mas também uma **definição/descrição completa** da sua **estrutura** e **restrições;**
- **Isolamento** entre programas e dados, e abstração de dados;
	- A estrutura dos arquivos de dados é armazenada no catálogo de dados, separada dos programas de acesso ( independência dos dados);
		- **Independência <span style="color:#83a598">Lógica</span> de Dados:** Refere-se à capacidade de <span style="color:#83a598">mudar a estrutura lógica dos dados sem alterar os programas de aplicação.</span> 
		- **Independência <span style="color:#fb4934">Física</span> de Dados:** Refere-se à capacidade de <span style="color:#fb4934">mudar a estrutura física dos dados sem alterar a estrutura lógica ou os programas de aplicação.</span> 
	- Segundo ELMASRI e NAVATHE (2011, p. 19), a abstração de dados “refere-se à supressão de detalhes da organização e armazenamento de dados, destacando recursos essenciais para um melhor conhecimento desses dados”;
	- Em outras palavras, é possível **descrever o banco de dados sem ater-se a especificidades de hardware e software;**
- Suporte de **múltiplas visões** dos dados;
	- Uma vez que o banco de dados pode possuir vários usuários, cada usuário pode ter uma **visão específica** do banco de dados;
	- Uma visão é uma **maneira de observação dos dados** do banco de dados, que pode ser um subconjunto ou conter dados virtuais que são derivados do banco de dados original;
- Compartilhamento de dados e processamento de transação **multiusuário**;
	- O sistema de banco de dados deve permitir o acesso **simultâneo** de vários usuários.

# **6. TRANSAÇÕES <span style="color: #d79921">A.C.I.D.</span> ou <span style="color: #d79921">(D.I.C.A)</span>**

ACID é um termo que descreve as propriedades que garantem a integridade das transações em um banco de dados:

- **<span style="color: #d79921">A</span>**tomicidade
	- Garante que as transações sejam <u>indivisíveis</u> (atômicas), ou seja, ou elas ocorrem em sua <u>totalidade</u>, ou <u>nenhuma</u> delas ocorrem.
	- **COMMIT:** operação utilizada quando a transação é <u>concluída com sucesso</u> (e os dados são alterados salvos em disco)
	- **ROLLBACK:** operação utilizada se <u>houver falha</u> nas operações da transação, o banco retornará ao estado anterior ao início da operação.
	- Responsável: Subsistema de controle de transações

- **<span style="color: #d79921">C</span>**onsistência
	- A transação deve respeitar as <u>regras de integridade</u> dos dados, levando o banco de dados de um <u>estado consistente</u> para outro estado de consistência.
	- Responsável: Subsistema de Controle de Integridade

- **<span style="color: #d79921">I</span>**solamento
	- Essa propriedade evita que transações que ocorram simultaneamente <u>interfiram uma nas outras</u>. Para que uma transação leia os dados gravados por outra, é preciso que a outra esteja concluída.
	- Responsável: Subsistema de Controle de Concorrência

- **<span style="color: #d79921">D</span>**urabilidade
	- Significa que os efeitos da transação são <u>permanentes</u>, isto é, que as alterações foram registradas e que somente poderão ser alteradas por outra transação bem-sucedida posterior.
	- Responsável: Subsistema de Recuperação

# **7. ARQUITETURA DE TRÊS ESQUEMAS**

Conceitos relevantes

- **Esquema** é a “descrição formal da estrutura de um banco de dados” (Heuser, 2004)
- “O conjunto de informações contidas em determinado banco de dados,em um dado momento, é chamado **instância** do banco de dados” (SILBERSCHATZ; KORTH;SUDARSHAN,1999,p.6).

A arquitetura de três esquemas ( **arquitetura ANSI/SPARC** ), é uma arquitetura para sistemas de banco de dados e tem o objetivo de separar as aplicações do usuário do banco de dados físico.

![[ansi_sparc.png]]

É organizada em **<span style="color: #d79921">três níveis</span>**:

- **Nível <span style="color: #d79921">Externo ou Visão</span>**: cada esquema externo descreve a **parte do banco de dados** que um dado grupo de usuários tem interesse e oculta o restante do banco de dados desse grupo.
- **Nível <span style="color:#d3869b">Conceitual</span>:** descreve a estrutura global do banco de dados como um todo, mas não fornece detalhes do modo como os dados estão fisicamente armazenados.
- **Nível <span style="color:#83a598">Interno</span>**: descreve a estrutura de **armazenamento físico** do banco de dados, utiliza um modelo de dados e descreve detalhadamente os dados armazenados e os caminhos de acesso ao banco de dados.

# **8. INDEPENDÊNCIA DE DADOS**

É a capacidade de **mudar o esquema em um nível** do sistema de banco de dados **sem** que ocorram **alterações** do esquema no **próximo nível mais alto**.

(1) **Independência LÓGICA de dados** é a capacidade de alterar o <span style="color:#d3869b">esquema conceitual</span> sem ter de alterar os <span style="color: #d79921">esquemas externos</span> ou programas de aplicação.

(2) **Independência FÍSICA de dados** é a capacidade de alterar o <span style="color:#83a598">esquema interno</span> sem ter de alterar o <span style="color:#d3869b">esquema conceitual</span>.

# 9. Balanceamento de Carga por Transação e princípio de failover

## **Definição de Balanceamento de Carga por Transação**:

Em um verdadeiro balanceamento de carga por transação, <span style="color:#83a598">**cada transação individual pode ser encaminhada para qualquer réplica disponível e otimizada no momento**</span>, independente de onde as transações anteriores foram processadas. Isso permite uma distribuição mais uniforme da carga e uma utilização mais eficiente dos recursos.

## **Princípio de Failover e Replicação de Estados**:

Sistemas bem projetados de balanceamento de carga, failover e replicação de estados procuram <span style="color:#83a598">minimizar dependências únicas e promover a rápida recuperação</span> ou redirecionamento em caso de falha de uma réplica. Eles garantem que as transações possam ser rapidamente retomadas em outra réplica sem perda de estado ou dados.

Para o balanceamento de carga , é de suma importância a atividade de replicação de dados.

- Existem diferentes modelos de replicação de dados, como, por exemplo:
	- Tranca distribuída: as transações são enviadas para todos os nós de forma síncrona. As consultas, por sua vez,  são distribuídas entre os servidores, conforme as regras de balanceamento de carga. Logo, observa-se que essa questão está errada,
	- Replicação de cópia primária: as transações são encaminhadas para um único servidor
	- Replicação tardia: alternativa à replicação imediata

- **Recebimento da Transação**: Quando uma solicitação de transação chega, o sistema de balanceamento de carga avalia as réplicas disponíveis do banco de dados.
- **Avaliação de Carga e Saúde**: O balanceador verifica a carga de trabalho atual, saúde e desempenho de cada réplica para determinar a melhor réplica para lidar com a transação.
- **Encaminhamento da Transação**: A transação é encaminhada para a réplica selecionada. Esta seleção pode ser baseada em vários fatores, como menor tempo de resposta, menor carga de trabalho, ou até de forma rotativa.
- **Processamento e Resposta**: A réplica do banco de dados processa a transação e retorna o resultado. O estado da transação pode ser replicado para outras réplicas para manter a consistência e facilitar o failover.
- **Failover e Recuperação**: Em caso de falha de uma réplica, o sistema de balanceamento de carga redireciona as novas transações para outras réplicas saudáveis e, se possível, recupera o estado da sessão a partir de réplicas sincronizadas.
