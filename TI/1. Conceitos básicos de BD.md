# 1. BD

## 1.1 Conceitos

 Um <u>banco de dados</u> é uma **<font color="#ff0000">coleção de dados logicamente relacionados</font>** que **<font color="#ff0000">representam algum aspecto do mundo real</font>**, podendo ter qualquer tamanho e complexidade, e podendo ser manual ou computadorizado. Comumente representado por um <font color="#ff0000">cilindro</font>.

Um **<u>sistema gerenciador de banco de dados</u>** é uma **<font color="#ffff00">coleção de programas</font>** que permite aos usuários **<font color="#ffff00">criar e manter um banco de dados</font>**, facilitando os processos de: 
- Definição 
- Construção
- Manipulação 
- Compartilhamento 
- Proteção 
- Manutenção

## 1.2 Características

- Autodescrição 
- Isolamento
- Suporte de múltiplas visões
- Compartilhamento de dados e processamento multiusuário

# 2.Transações

Uma transação é um programa em execução ou processo que inclui um ou mais acessos ao BD.

## 2.1 Atomicidade

Uma transação é uma unidade de processamento atômica que **<font color="#d83931">deve ser executada integralmente até o fim ou não deve ser executada.</font>** Se ocorrer tudo bem, devem ser confirmadas (<font color="#00b0f0">COMMIT</font>). Caso ocorra falha, devem ser desfeitas (<font color="#d83931">ROLLBACK</font>)

## 2.2 Consistência

A transação deve respeitar as **<font color="#de7802">regras de integridade</font>** dos dados, levando o banco de dados de um **<font color="#de7802">estado consistente </font>**para outro estado de consistência. <u>Estado de consistência é aquele que respeita todas as regras e restrições de integridade dos dados</u>.

## 2.3 Isolamento 

Essa propriedade evita que transações que ocorram simultaneamente <font color="#245bdb">interfiram uma nas outras.</font> Para que uma transação leia os dados gravados por outra, é preciso que a outra esteja concluída

## 2.4 Durabilidade

Significa que os efeitos da transação são permanentes, isto é, que as alterações foram registradas e que somente poderão ser alteradas por outra transação bem-sucedida posterior

# 3. Arquitetura ANSI/SPARC (3 Esquemas)

- <font color="#d83931">Esquema</font> é a <font color="#c00000">descrição da estrutura</font> de um BD. 
- <font color="#00b050">Instância</font> é o conjunto de dados armazenados no BD em um <font color="#00b050">determinado momento da operação</font>. 

## 3.1 Nível Externo ou Visão 

Cada esquema externo descreve a **parte do banco de dados** que um dado grupo de usuários tem interesse e oculta o restante do banco de dados desse grupo

## 3.2 **Nível Conceitual**

Descreve a estrutura global do banco de dados como um todo, mas não fornece detalhes do modo como os dados estão fisicamente armazenados.

## 3.3 **Nível Interno**

Descreve a estrutura de **armazenamento físico** do banco de dados, utiliza um modelo de dados e descreve detalhadamente os dados armazenados e os caminhos de acesso ao banco de dados.

# Independência de dados

- **Independência <font color="#00b050">LÓGICA</font> de dados**: Capacidade de alterar o <font color="#00b050">esquema conceitual sem ter de alterar os esquemas externos</font> ou programas de aplicação
- Independência <font color="#7030a0">FÍSICA</font> de dados: Capacidade de alterar o <font color="#7030a0">esquema interno sem ter de alterar o esquema conceitual.</font>
